# Hasil Uji End-to-End: Sidecar MCP Midscene

Tanggal: 2026-08-04
Model VLM: `openai/gpt-5.6-luna` via OpenRouter, `MIDSCENE_MODEL_FAMILY=gpt-5`
Target uji: `https://example.com`

Semua angka di bawah berasal dari eksekusi nyata terhadap browser sungguhan dan model
berbayar sungguhan, bukan dari pembacaan kode.

## Yang terbukti bekerja

### Tahap A — browser nyata, tanpa biaya

`start_session` membuka Chrome dan menavigasi dalam 1375 ms. `screenshot` mengembalikan
PNG **44.572 byte, 2880×1800**.

Dua hal yang dibuktikan angka itu:

- **2880×1800 = 1440×900 dengan `deviceScaleFactor: 2`.** Perbaikan viewport dari review
  Task 9 mendarat di dunia nyata. Tanpa perbaikan itu, puppeteer memakai default beku
  800×600 — 3,6× lebih sedikit piksel sebelum re-encode JPEG q90 Midscene.
- **PNG-nya asli, header valid.** Membuktikan `uraikanDataUriGambar` bekerja. Kode rencana
  yang asli (`String(base64 ?? '')` atas `logScreenshot()`) akan menghasilkan blok gambar
  kosong selamanya, tanpa error.

`start_session` juga benar-benar membuka URL yang diminta — parameter `url` yang dulu
dideklarasikan tapi dibuang diam-diam kini hidup.

### Tahap B — operasi AI berbayar

| Operasi | Waktu | Hasil |
|---|---|---|
| `assert` | 5076 ms | lulus, budget terpotong 1 dari 12 |
| `query` | 3359 ms | `{"heading": "Example Domain"}` |
| `screenshot` | 61 ms | gratis, budget tidak berubah |

Ekstraksi terstruktur bekerja terhadap halaman nyata, dan akuntansi budget sesuai
dokumentasi: `assert`/`query` menagih, `screenshot` tidak.

### Tahap C — guard, replay, cache, walkthrough

**Kedua guard menyala dengan benar**, sebelum browser dibuka:

- Bentuk `runGherkinScenario` → `SCENARIO_UNSUPPORTED` dalam 1 ms
- Bentuk `flow` sebagai mapping → `SCENARIO_UNSUPPORTED` dalam 1 ms

Keduanya adalah perbaikan dari final review, dan keduanya nyata bekerja — bukan sekadar
lulus unit test.

**Cache terbukti**, memakai skenario yang benar-benar melokasikan elemen (`aiTap`):

| | Waktu | Cache |
|---|---|---|
| Run 1 (dingin) | 10.771 ms | berkas ditulis |
| Run 2 (hangat) | 3.901 ms | cache hit |

**2,76× lebih cepat.** Bukan sekadar selisih waktu — isi cache-nya konkret:

```yaml
midsceneVersion: 1.10.8
cacheId: midscene-mcp-web
caches:
  - type: locate
    prompt: the "Learn more" link below the paragraph
    cache:
      xpaths:
        - /html/body/div[1]/p[2]/a[normalize-space()="Learn more"]
```

dan log Midscene mencatat `cache hit`. Run kedua memakai ulang XPath tersimpan alih-alih
memanggil model. Ini bukti definitif bahwa perbaikan `cache: { id: cacheId }` dari final
review benar-benar membangun `TaskCache` — sebelumnya hanya `cacheId` yang dioper, jalur
legacy yang butuh env var `MIDSCENE_CACHE` dan tanpa itu tidak membuat cache sama sekali.

**Rantai lengkap:** `run_scenario` menulis report 2.333.663 byte, dan `build_walkthrough`
menghasilkan panduan HTML 191.350 byte dari report itu.

### Tahap D — lewat agen ACP sungguhan

`claude-agent-acp` 0.64.2, `authMethods: []` (memakai kredensial Claude Code yang sudah
ada — premis langganan bertahan). Sesi dibuat, lalu agen ditanya tool apa yang tersedia:

**10 dari 10 tool Midscene terlihat** sebagai `mcp__<nama>__*`.

Diverifikasi dengan nama server unik (`probemid`), bukan `midscene`, untuk memastikan
tool-nya datang dari konfigurasi ACP yang dikirim klien dan bukan dari konfigurasi Claude
Code milik pengguna.

## Cacat yang ditemukan uji E2E, dan diperbaiki

**`run_scenario` tidak menavigasi ke mana pun.** Ia memanggil `sessions.start(target)`
tanpa URL, jadi browser diam di halaman kosong dan setiap assertion gagal. Keluaran
aslinya:

```
[DEVICE_FAILED] task - periksa beranda: Assertion failed: ...
Reason: The screenshot is entirely dark and contains no visible page heading
```

Artinya mekanisme replay — fondasi seluruh model biaya proyek ini — tidak berfungsi untuk
target web. Lolos dari 86 unit test karena semuanya memakai `FakeDevice`, yang tidak
punya konsep halaman.

Diperbaiki: `run_scenario` kini mengambil URL dari YAML skenario (memakai ulang
`resolveWebTarget` milik Midscene, yang menangani alias `page`/`browser`/`web`/`target`
dan melempar bila lebih dari satu dipakai), dengan argumen `url` opsional sebagai
override, dan galat terstruktur bila skenario web tidak menyediakan URL sama sekali.

## Koreksi terhadap temuan sebelumnya

Dokumen rencana sempat menyatakan sebagai **keharusan** bahwa klien ACP harus
menghilangkan field `type` untuk server MCP stdio, karena `type: "stdio"` eksplisit akan
membuat server **dibuang diam-diam**. Dasarnya cabang `else if (!("type" in server))` di
`dist/acp-agent.js`.

**Itu terbukti salah.** Diuji dua kali terhadap `claude-agent-acp` 0.64.2 dengan nama
server unik — tanpa `type` dan dengan `type: "stdio"` — dan keduanya menghasilkan 10/10
tool terlihat. Ada lapisan validasi yang membuang field itu sebelum mencapai pemetaan.

Bentuk tanpa `type` tetap yang dianjurkan karena itu varian stdio yang sebenarnya di
skema, tetapi klaim kegagalan senyap itu tidak berlaku.

## Temuan sampingan yang mengikat Rencana 2

Sesi ACP **mewarisi server MCP milik pengguna** dari konfigurasi Claude Code-nya,
digabung dengan yang dikirim klien:

```js
mcpServers: { ...(userProvidedOptions?.mcpServers || {}), ...mcpServers }
```

Pada mesin uji, agen melihat `pencil` dan `mobbin` milik pengguna di samping server kita.
Aplikasi tidak boleh berasumsi hanya tool-nya sendiri yang tersedia di sesi.

## Yang masih belum diuji

- **Target `computer` (desktop macOS).** Butuh izin Accessibility dan Screen Recording —
  dua pemberian TCC terpisah yang tidak diperiksa saat startup.
- **`codex-acp`.** Butuh login interaktif (`authMethods` menawarkan `api-key` dan
  `chat-gpt`).
- **Situs SPA.** Adapter memakai `waitUntil: 'domcontentloaded'` sedangkan skrip yang
  sudah terbukti memakai `networkidle2` dengan timeout 60 detik. `example.com` terlalu
  sederhana untuk menguji perbedaan ini.
